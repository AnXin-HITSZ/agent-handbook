# 使用示例

收录实际使用资产后的脱敏记录，帮助判断适用范围并发现需要改进的指令。目前尚未收录案例；以下是记录格式说明，不代表已发生的使用结果。

## 收录标准与记录方式

每份记录应包含：
- 场景：任务目标、必要背景，以及影响结果的工具或环境信息。
- 采用的资产：使用相对链接指向真实资产，必要时注明使用日期或版本标识。
- 必要调整：替换了哪些输入、调整了哪些步骤，以及原因。
- 观察结果：实际输出、人工检查方式、有效部分、失败或不确定之处；区分观察与推测。

创建普通 Markdown 文件，按[命名约定](../docs/naming-conventions.md)命名，并在此索引真实存在的记录。使用前对照自身场景，参考调整方法，不将单次结果视为普遍保证。

发布前脱敏：移除身份信息、真实密钥、内部地址、个人绝对路径及不应共享的代码或业务数据。保留理解任务所需的最小上下文，不以伪造成功案例填充目录。
