# 资产编写与维护指南

## 选择合适的形式

| 形式 | 适用场景 | 放置位置 |
| --- | --- | --- |
| 一次性 Prompt | 在一次对话中完成具体任务，可通过替换输入再次使用 | [prompts](../prompts/README.md) |
| 可复用 Skill | 有稳定流程，可能需要脚本、参考材料或其他资源 | [skills](../skills/README.md) |
| 项目级指令文件 | 长期适用于整个项目或指定范围的背景、命令和协作约定 | [templates](../templates/README.md) |

先采用能清楚表达需求的简单形式。只有在实际复用需求出现时才拆分配套资源；不同工具的加载规则、元数据与能力不同，按目标工具说明调整。

## 写清五件事

1. **目标**：描述可观察的任务结果，例如“解释一个函数的数据流并用输入示例验证”，避免“全面提升能力”等难以检验的表述。
2. **输入**：列出必要背景、文件范围和约束，使用明确占位符；说明输入缺失时应如何处理。
3. **步骤**：按依赖顺序给出可执行动作，明确何时需要等待用户回答，避免重复和相互矛盾的要求。
4. **边界**：说明工作范围、不能假设的信息，以及读取、修改或运行操作的授权范围。不要把资产文本本身当作执行授权。
5. **输出**：规定有用的结构、详略和验证证据，要求区分事实、推断和未验证部分。

将使用说明与可复制正文分开。项目模板应保留可编辑背景和命令字段，不猜测技术栈，不建立无必要的审批流程。

## 通过使用改进

先在一个具体、可控的场景中使用，检查输出是否满足目标。将实际输入范围、必要调整、观察结果与局限记录到 [examples](../examples/README.md)，并脱敏。尚未使用的资产可以收录，但不得声称已经验证有效。

依据记录修订原资产，优先减少歧义、补足缺失边界或改进输出要求。不默认维护多个重复版本；只有适用场景存在实质差异时才拆分，并在索引中说明区别。

## 修改后检查

- 保留无关内容与已有用户改动，确认修改围绕实际需求。
- 遵循[命名约定](naming-conventions.md)，同步分类索引和必要导航。
- 逐一检查相对链接、占位符说明、命令是否明确待填或已核实，以及跨文件约定是否一致。
- 检查密钥、私人信息、个人绝对路径及未经验证的效果承诺。
- 不因文档维护引入无必要的依赖或自动化；使用记录应如实说明未验证项。
