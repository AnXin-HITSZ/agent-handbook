# 命名与组织约定

## 命名与分类

- 文档主要使用简体中文，目录和普通文件名使用英文小写，多个单词以连字符分隔，例如 `guided-code-learning.md`。
- 保留工具约定名称：`README.md`、`AGENTS.md`、`CLAUDE.md`、`SKILL.md`。
- Prompt 按任务主题分类；Skill 通常一个独立目录；项目级模板按工具及适用场景分类。
- 仅在已有真实内容需要归类时创建目录，避免空分类、重复资产和含糊的 `misc` 分类。
- 文件名表达稳定用途，避免默认使用 `final`、`new`、`v2` 等版本后缀；优先利用 Git 历史追踪修订。

## 占位符

统一使用 `{{含义明确的名称}}`，例如 `{{学习目标}}`、`{{执行目录及检查测试命令}}`。资产应说明每个占位符所需的信息以及替换时机。

模板和 Prompt 源文件允许保留设计好的占位符；复制使用前须全部替换或删除不适用项。无法确认的信息明确标为未知，缺失的命令写“未配置”，不要填写看似可用的虚构值。不要将真实密钥、私人信息或个人绝对路径作为示例值。

## 链接与索引

- 仓库内导航使用相对于当前文档的 Markdown 链接，保持 GitHub 可用，不使用本机路径或 `file://` 链接。
- 链接的大小写与目标文件保持一致；目录导航优先链接到对应 `README.md`。
- 新增、移动或重命名资产时同步分类索引和受影响的链接，只索引真实文件。
- 如确需外部资料，使用完整的 HTTPS 地址，并说明资料用途。
